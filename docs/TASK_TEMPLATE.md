## 任务分配原则

1. **一个任务一个模块。** 不要把跨模块的重构作为单个任务分发。
2. **接口变更单独成任务。** 不要让成员顺手"改善"公共签名。
3. **P0 先做**：P0 是阻塞其他任务的前置项。
4. **缺陷修复单独编号。** 不与功能任务混合 —— 否则无法验证修复是否引入回归。
5. **每份任务必须带验收标准。** 没有验收标准的任务不要分发。

## 跨模型协作约定

无论成员使用 Claude、GPT 还是其他代理：

1. **读同一份规则**：`AGENTS.md` + `docs/interfaces.md`。
2. **基于当前代码实现**，不基于对项目的想象。开工前先读实际源码。
3. **允许/禁止文件以任务单为准**，不得擅自扩大范围。
4. **跑同一组测试**，贴同一份真实输出。
5. **未经批准不增依赖。**
6. **接口不足以完成任务时，先提变更建议**，不自行修改。
7. **质量由自动测试和代码审查判定**，与使用的模型无关。
8. **不同实现必须通过同一组契约测试** —— 这是跨实现可集成的唯一保证。
